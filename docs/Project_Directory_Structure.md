# Project Directory Structure

## Overview

The VideoQA project uses a dual-storage architecture:

1.  **GitHub Repository** --- version-controlled notebooks, source code,
    datasets, and documentation.
2.  **Google Drive Project Storage** --- persistent datasets, trained
    models, representations, prediction artifacts, and evaluation
    results.

GitHub is the authoritative implementation. Google Drive stores
generated artifacts.

------------------------------------------------------------------------

## GitHub Repository Structure

``` text
videoqa-representation-comparison/
├── datasets/
├── docs/
├── notebooks/
├── src/
└── README.md
```

  Directory   Purpose
  ----------- -------------------------------------------
  datasets    NExT-QA metadata and question files
  docs        GitHub Pages documentation
  notebooks   Colab notebooks implementing the workflow
  src         Shared Python modules and configuration

## Notes

-   GitHub is the authoritative implementation.
-   clip_text representations are shared across both
    representation-based methods.
-   clip_video representations are reusable but used only by the CLIP
    representation method.
-   autoencoder_video representations are experiment-specific.
-   Notebook 07 combines clip_text with either clip_video or
    autoencoder_video using a Fusion MLP classifier.
-   Notebook 08 evaluates all methods using the same multiple-choice
    evaluation framework.
